# Mac mini 로컬 노트 비밀번호 관리

이 기능은 Mac mini 포털과 해당 포털의 터널 주소에만 적용됩니다. Vercel의 노트 비밀번호/기존 환경변수 인증은 그대로이며 동기화하지 않습니다. `api/note-admin.js`는 Vercel에서 항상 `503 / LOCAL_ONLY`를 반환하고 로컬 파일 모듈을 불러오지 않습니다. 기존 Vercel note2의 콘텐츠 저장 구현은 이번 인증 변경 범위가 아닙니다.

## 승인 후 최초 적용

**아래 명령은 운영 저장소를 생성할 수 있습니다. 운영자 승인 및 현재 포털의 실행 환경 확인 후에만 실행합니다. 테스트는 운영 파일을 사용하지 않습니다.**

1. 현재 포털과 같은 사용자 계정/환경에서 `~/.dashboard_pw`가 존재하며 비어 있지 않은지 확인합니다. 비밀번호 원문은 터미널/채팅에 출력하지 않습니다.
2. 현재 포털의 `NOTE_PASSWORD`, `NOTE2_PASSWORD`, `NOTE_DIR`, `NOTE2_DIR` 설정이 있다면 그대로 유지합니다. 새 비밀번호를 지정하는 것이 아니라 기존 환경을 그대로 인계해야 합니다.
3. 기본 저장소는 `~/.config/aaaa/note-auth.json`입니다. 다른 경로를 쓰려면 저장소 밖의 전용 디렉터리 경로로 `NOTE_AUTH_FILE`을 지정합니다. 이 설정은 초기화와 포털 실행에 동일하게 전달합니다. 디렉터리는 0700, 파일은 0600이어야 합니다. 심볼릭 링크나 저장소 내부 경로는 거부합니다.
4. 명시적인 로컬 초기화(선택):
   ```sh
   cd /Users/chojiks/github-aaaa
   node scripts/init-note-auth.js --initialize
   ```
   이미 저장소가 있으면 검증만 하고 덮어쓰거나 비밀번호를 바꾸지 않습니다.
5. 승인된 재시작 시 기존 포털 프로세스 관리 방식과 기존 환경을 유지하여 실행합니다. 직접 실행 예시(기존 8087 프로세스가 종료된 뒤에만):
   ```sh
   HOST=127.0.0.1 PORT=8087 node portal-server.js
   ```
   포털은 리슨하기 전에 같은 초기화 함수를 실행하므로 4단계는 생략할 수 있습니다. 초기화 실패 시 노트 로그인/관리 기능은 fail-closed로 차단됩니다. 다른 포털 페이지는 계속 제공됩니다.

## 최초 이관/변경 규칙

- 관리자: `NOTE_ADMIN_PASSWORD_FILE` 또는 기본 `~/.dashboard_pw`를 최초 1회 읽습니다. 파일이 없거나 비어 있으면 새 저장소를 만들지 않습니다. HTTP 초기화 API는 없습니다.
- 노트 A/B: 기존 환경변수 > 기존 `.note-password` 파일 > 기존 기본 비밀번호 순서로 최초 1회 이관합니다. 원본 파일은 변경하지 않습니다.
- 이후에는 로컬 JSON의 salted scrypt 검증값이 유일한 인증 원본입니다. 환경변수/기존 비밀번호 파일을 편집해도 이미 생성한 로컬 저장소를 덮어쓰지 않습니다. 관리자 로그인도 최초 이관한 관리자 비밀번호를 사용합니다.
- `/detail-admin-jik-2026.html`에서 별도 관리자 인증 후 노트 A/B를 변경합니다. 관리자 세션은 15분입니다. 변경 시 revision 및 랜덤 토큰 키를 갱신하여 해당 노트의 기존 토큰을 무효화합니다. 같은 비밀번호로 다시 저장해도 무효화합니다.
- 로컬 노트 A/B 사용자 인증은 고정 7일 만료 없이 현재 revision/서명 키로 지속 검증합니다. 새 사용자 토큰은 `exp`를 생략하며 기존 사용자 토큰의 과거 `exp`도 무시하되 id·room(노트 B)·revision·서명은 항상 검증합니다. 브라우저 토큰은 localStorage에 유지하며 비밀번호 평문은 저장하지 않습니다. 관리자 토큰은 별도로 유한한 미래 `exp`가 필수이고 15분 만료를 유지합니다.
- 관리자 로그인은 파일에 유지되는 전체 10회/15분 예산과 소켓 기반 제한이 적용됩니다. 노트 로그인은 소켓 기준 5회 실패 시 1시간 잠깁니다. 터널에서는 같은 로컬 소켓으로 묶이므로 일부 이용자가 함께 제한될 수 있습니다. 위조 가능한 IP 헤더로 우회시키지 않기 위한 보수적 정책입니다. 노트 제한은 프로세스 재시작 시 초기화됩니다.
- 쓰기는 전용 잠금 파일 + 0600 임시 파일 + fsync + atomic rename으로 수행합니다. 프로세스 비정상 종료로 `.lock`이 남으면 자동 잠금 해제하지 않습니다. 포털 프로세스가 모두 중단되었음을 확인한 운영자만 잠금을 제거할 수 있습니다. JSON 원본은 삭제하지 마세요(삭제 후 다음 시작은 기존 비밀번호로 최초 이관을 시도합니다).
- 백업에는 JSON 전체를 0600으로 보관해야 합니다. 해시/토큰 비밀이 있으므로 공개 저장소, 웹 루트, Vercel 환경에 넣지 않습니다.

## 검증

```sh
node --test tests/*.test.js
node scripts/build-static.js
```

통합 테스트는 임시 디렉터리와 127.0.0.1의 임의 포트만 사용하며 재시작, 회전, 인증, 정적 파일 유출 차단, Vercel 인증 독립성을 검증합니다. 빌드 출력은 허용된 공개 파일만 포함하고 기존 출력의 잔여 파일도 제거합니다. 운영 포털 재시작/배포는 테스트에 포함되지 않습니다.
